# SOC Investigation Workflow

## Objective

This document describes the standard workflow followed by a Security Operations Center (SOC) analyst while investigating security alerts.

## Workflow

Alert
↓
Triage
↓
Collect Evidence
↓
Investigate
↓
Determine Severity
↓
Contain / Escalate
↓
Document

## 1. Alert

An alert is generated by a SIEM or EDR when suspicious activity is detected.

Examples:
- Multiple failed login attempts
- Malware detection
- Suspicious PowerShell execution

## 2. Triage

The analyst performs an initial review to determine whether the alert requires investigation.

Checks include:
- Username
- Timestamp
- Source IP
- Device name
- Alert type

## 3. Collect Evidence

Relevant evidence is gathered from different security tools.

Evidence includes:
- Event logs
- IP address
- Login history
- Endpoint information
- Process activity

## 4. Investigate

The collected evidence is analyzed to determine whether the activity is malicious or benign.

Possible outcomes:
- False Positive
- True Positive

## 5. Determine Severity

Severity is assigned based on business impact.

- Low
- Medium
- High
- Critical

## 6. Contain / Escalate

If the threat is genuine:
- Escalate to L2 analyst
- Isolate affected endpoint when authorized
- Block malicious IP when authorized
- Follow the organization's incident response procedure

## 7. Document

The investigation is documented in the incident ticket.

Documentation should include:
- Alert details
- Evidence collected
- Investigation findings
- Severity
- Actions taken
- Final status

## Conclusion

A SOC analyst follows a structured workflow to ensure every security alert is investigated consistently, accurately, and documented properly.
